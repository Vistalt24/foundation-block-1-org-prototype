# Foundation — Организационная структура (v1 Shell)

Живой UX-прототип модуля «Организационная структура» внутри полноценной
оболочки Foundation (Application Shell): Dashboard, навигация, модуль
«Структура» (Рабочий вид + Карта структуры + Таблица — одна общая модель
данных), Помощник, Техподдержка, Настройки, роли.

Один файл (`index.html`), без сборки и без бэкенда — состояние живёт в
памяти вкладки браузера. Интерфейс полностью на русском.

## Открыть

Публичная ссылка (без установки, без авторизации):
**https://vistalt24.github.io/foundation-block-1-org-prototype/**

Локально — открыть `index.html` двойным кликом, либо:

```
python -m http.server 8000
```

и открыть `http://127.0.0.1:8000/`.

## Что внутри

- **Application Shell**: верхняя панель (burger, раздел, организация,
  состояние программы, язык, уведомления, помощник, профиль/роль),
  левая навигация (Dashboard, Люди, Роли и права, Организация,
  Структура, Проекты, Настройки, Техподдержка).
- **Dashboard** — первый экран, карточки всех модулей с состояниями
  «Не настроено» / «Требует внимания» / «Готово».
- **Модуль «Структура»** — одна общая модель данных (`nodes`/`employees`),
  два самостоятельных экрана поверх неё:
  - **Рабочий вид** (Список / Таблица) — точная работа: карточки, люди,
    изменения;
  - **Карта структуры** — по центру, во всю рабочую область, с zoom,
    fit to screen, Focus mode на ветку, Drag & Drop узлов.
  Переход между экранами — явными кнопками («Карта структуры» /
  «Вернуться в рабочий вид»), с сохранением выбранного объекта.
  Изменение в любом из экранов (перенос узла, сотрудника, руководитель,
  Primary/Secondary, архивация) сразу видно в обоих.
- **Drag & Drop** — узлов (перенос/смена родителя, защита от циклов,
  подсветка допустимых/недопустимых зон, Impact Preview перед
  подтверждением) и сотрудников (перенос между отделами / добавление в
  проект, с явным выбором Primary или Secondary при переносе). Работает
  и в Рабочем виде, и на Карте. Всегда есть альтернативный путь через
  контекстную панель.
- **Контекстная панель** — не постоянная, открывается по клику на узел
  или сотрудника; вторичные действия — в «Ещё».
- **Smart Unassigned, Vacant Lead, Temporary Structure** — визуально
  выделены везде (дерево, карта, карточка).
- **Роли** (Owner / Structure Admin / HR / Department Manager / Employee /
  Viewer) — реально блокируют действия в контекстной панели
  (🔒 admin-only / read-only). Смена демо-роли — через меню профиля.
- **Настройки** — Личные (язык, вид, уведомления), Организация (название,
  страна, timezone, locale, состояние программы — owner-only, с
  подтверждением), Инфраструктура/Загрузка — рабочий импорт CSV: шаблон,
  предпросмотр, проверка отдела по названию, подтверждение, журнал
  загрузок (реально добавляет сотрудников в структуру).
- **Помощник** — доступен с любого экрана (иконка в топбаре и плавающая
  кнопка), видит контекст (экран/роль/объект), отвечает по Help
  Contract на ключевые действия, и при "не помогло" создаёт обращение в
  Техподдержку с полным диагностическим контекстом (Error ID, User ID,
  Organization ID, Role, Screen ID, Object ID, Action ID, timestamp).
- **Техподдержка** — список обращений + форма создания, независимая от
  Помощника.
- Демо-компания «Стройсервис» — 50 сотрудников, 4 постоянных отдела (один
  без руководителя — Vacant Lead), 2 бригады, 1 временный проект,
  1 Secondary-связь, 1 временное основное назначение (override), 1 в
  «Требуют назначения».

## Дизайн

Токены — подтверждённая палитра Student Brandbook (bg-page/bg-surface/
text-primary/accent-terra и т.д.), без изменений значений. Несколько
семантических токенов (danger/warn/good/unassigned) отсутствовали в
исходной палитре и добавлены как Foundation-токены (не хардкод) — см.
комментарий в начале `<style>`.

## Ограничения

- Состояние живёт только в памяти вкладки — обновление страницы
  сбрасывает изменения к исходным демо-данным.
- Люди / Роли и права / Организация / Проекты — лёгкие рабочие страницы
  поверх той же модели данных, не полноценные отдельные модули.
- Реального i18n-движка нет — переключатель языка есть и работает как
  контрол, второй язык — заглушка "скоро".
- GitHub Pages может обновляться до ~1–2 минут после push.
